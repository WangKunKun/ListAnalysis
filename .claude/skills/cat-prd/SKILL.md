# 品类报告 → 自包含 PRD

读品类分析报告(`reports/{日期}-品类分析-{slug}.md`),交互确认 3 个关键决策,
生成一份**完全自包含**的 PRD——拿到任何其他项目、任何 AI 编码工具会话,零依赖
即可依次实现。
设计文档:docs/superpowers/specs/2026-08-25-cat-prd-design.md

## 参数解析

品类 slug(必填,定位报告;给的是品类名则模糊匹配最近的报告并复述确认);
平台 `ios|android|cross`(可选,预答交互问题 1);商业模式
`buyout|subscription|free-ad`(可选,预答交互问题 2)。

## 流程

1. **定位报告**:
   - 优先查找品类分析报告: `reports/*-品类分析-{slug}.md`(多份取最新)
   - 如不存在，降级查找工具榜报告: `reports/*-工具榜分析*.md`
     (文件名可能带 -{platform} 后缀)
   - 找不到 → 提示先跑分析(品类用 `/cat-scan`,工具榜用 `/app-scan`),停止。
   - 报告快照日期(文件名里的日期)距今 > 90 天 → 提示数据可能过时、建议
     重跑分析,不阻塞。
2. **交互 3 问**(命令参数已答的跳过;每问附报告中的证据辅助决策):
   - 目标平台:ios / android / cross
   - 商业模式:buyout(买断)/ subscription(订阅)/ free-ad(免费+广告)
     ——附报告变现证据(如"本品类买断制口碑溢价 4.9 分 vs 订阅墙差评占 30-40%")
   - 主定位:
     - 如果是品类分析报告：列出报告"机会点"节的内容供选择
     - 如果是工具榜报告：提取"类型分布"和"观察与机会"章节内容供选择
     - 提供"AI 推荐"选项(推荐时按痛点强度 × 竞争空白给出理由)
3. **生成 PRD**:按下方结构写作,落盘 `reports/{今天日期}-PRD-{slug}.md`。
4. **执行摘要**:向用户输出 3-5 句(一句话定位、P0 范围、里程碑数)。

## PRD 结构(10 节,全自包含)

0. **使用说明(给 AI 编码工具)**:本文档按里程碑依次实现;每个功能完成后
   对照其验收标准(AC)自验;技术栈可按团队能力替换,但功能契约(AC)不变。
1. **产品概述**:品类定义与背景(从报告"品类概览"节内联)、一句话定位。
2. **目标用户与核心场景**:从报告推导的细分人群 × 场景(2-4 组)。
3. **定位与差异化主张**:
   - 内联品类分析报告的痛点证据(评论摘录+频率)或工具榜报告的观察结论
   - 引用竞品基准数据证明市场空白
   - 明确与现有产品的差异化主张
4. **竞品基准表**:
   - 从品类分析报告的竞争格局节提取数据,或从工具榜报告的应用列表提取
   - 包含双平台对比(如适用)
   - 标注数据快照日期
5. **功能规格**(主体,三层):
   - **P0 品类标配基线**:来自品类分析报告"标配功能"清单或工具榜报告的通用功能模式
   - **P1 差异化主打**:直接支撑第 3 节定位的功能
   - **P2 亮点增强**:基于痛点分析得出的增强点(品类分析)或观察机会(工具榜分析)
   每个功能块:ID(F-P0-01 / F-P1-01 / …)/名称/描述(1-3 句)/
   验收标准(1-4 条,可测试表述)/依赖(其他功能 ID 或"无")。
   AC 写法:描述可观察、可验证的行为("扫描 10 页导出单个 PDF 且页序正确" ✓;
   "体验流畅" ✗)。写不出 AC 的功能,回头重想描述。
6. **非功能需求**:从痛点推导(性能/隐私/离线/无广告等),每条同样可测表述。
7. **变现设计**:选定模式的具体方案(定价档/免费额度/触发付费的动作);
   显式列出"规避的竞品痛点"(如不设水印陷阱、不搞买断转订阅)。
8. **里程碑与实现顺序**:P0→P1→P2 各为一个里程碑;P0 内部按技术依赖排序
   (基础能力在前,如 相机捕获→边缘检测→导出,不倒序);每里程碑给
   "完成定义"(全部 AC 通过 = 完成)。
9. **附录**:名词表;数据来源声明(基于 {快照日期} 的品类快照,数字来自
   当期双平台应用商店公开数据)。

## 质量约束

- **自包含硬约束**:全文禁止"见品类报告 X 节"式引用;一切证据/表格/数字内联
- **数字不臆造**:竞品评分/下载量/价格只从品类报告抄录
- **全程中文**;技术名词保留英文

### 数据来源追溯(增强)
- 竞品数据标注来源: "基于{报告日期}的品类快照"
- 痛点证据标注来源app和评论数量
- 功能需求标注基于的分析维度

### 自包含验证
- PRD可单独交给外部AI工具实现
- 所有数据内联，无外部引用
- 技术栈可替换但功能契约不变

## 错误处理

### 报告定位错误
- **品类分析报告不存在**: 提示先运行品类分析: `/cat-scan '品类名'`，停止执行
- **工具榜报告缺失**: 降级提示运行工具榜扫描: `/app-scan`，停止执行  
- **报告格式不符**: 
  - 缺少"机会点"节 → 降级让用户口述主定位，交互式继续
  - 缺少"痛点分析"节 → 标注"痛点信息有限"，基于功能清单推导
  - 竞品数据缺失 → 提示报告可能不完整，建议重新分析

### 数据追溯错误
- **竞品数据过期(>90天)**: 标注警告"数据可能过时"，在PRD中标注数据快照日期，继续执行
- **数据来源模糊**: 强制标注来源应用和数据日期，确保可追溯性
- **功能描述不清**: 基于竞品功能对比推导，标注"推导功能"标识

### PRD生成错误
- **交互选择失败**: 提供默认选择(P0标配功能)，标注用户未确认
- **验收标准(AC)生成困难**: 降级为功能描述，提示需要补充可测试标准

### 用户友好提示
报错时说明原因与影响,并给出可执行的下一步命令(如 `/cat-scan '品类名'`)。
