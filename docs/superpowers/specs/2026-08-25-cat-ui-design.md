# /cat-ui:PRD → UI 设计规范与 Stitch 生成 — 设计文档

**日期:** 2026-08-25
**状态:** 已确认
**前置:** /cat-prd(2026-08-25)已上线,产出 `reports/{日期}-PRD-{slug}.md`;
演示产物 `reports/2026-08-25-UI设计规范-qr-code-generator.md` 已获用户认可,
其 6 节结构即本 skill 的输出模板。

## 1. 背景与目标

品类链路(扫榜 → 品类分析 → PRD)之后缺 UI 设计环。本 skill 把
"PRD → UI 设计规范 + Stitch prompts"固化:零交互,设计决策全部从 PRD 推导;
Stitch MCP 可用时自动生成设计稿,不可用时 prompts 即交付物。

**核心决策(用户确认):**

| 维度 | 决定 |
|---|---|
| 交互 | 零交互(风格从 PRD 定位推导,不问用户) |
| 自动化层级 | 智能后端:有 Stitch MCP 工具 → 自动生成;没有 → prompts 手动路径 |
| 输出结构 | 6 节模板(同演示产物) |
| 实现 | 纯 skill 文档,零代码 |

## 2. 命令形态

```
/cat-ui <品类 slug>
```

slug 定位 `reports/*-PRD-{slug}.md`(多份取最新;找不到 → 提示先跑
`/cat-prd {品类}` 并停止;PRD 日期 > 90 天 → 提示不阻塞)。

## 3. 流程(三步)

1. **读 PRD 推导设计**(零交互):
   - 设计方向:从定位与差异化主张推导 3 个关键词与风格基调
   - 设计系统 tokens:色板(浅/暗)、字阶、间距/圆角/阴影、核心组件规格
   - 信息架构:页面流(导航结构),屏数按 PRD 功能块推导,核心屏 ≤6
   - 每屏详规:目的/布局/关键元素/交互状态/空态
2. **产出文档** `reports/{今天日期}-UI设计规范-{slug}.md`,6 节结构:
   ①设计方向 ②设计系统 tokens ③信息架构与页面流 ④页面详细规范
   ⑤每屏 Stitch prompts(英文,统一 Style anchor 保证多屏一致)
   ⑥交付与衔接(Stitch → Figma 精修 → 编码工具的 tokens 对照)
3. **智能后端分支**:
   - 检测会话中是否可用 Stitch MCP 工具(工具列表/ToolSearch);
   - **可用**:逐屏用 §5 prompts 调 Stitch 生成,回报生成结果与项目/导出
     状态;单屏失败重试一次,再失败降级该屏为手动路径
   - **不可用**:文档 prompts 即交付物,执行摘要附一句"手动贴 Stitch"指引
   - MCP 全程失败不影响文档产出(文档永远完整)

## 4. 质量约束

- **功能可追溯**:每屏标注来源功能 ID(F-P0-01 等);付费/打断类 UI 决策
  必须引用 PRD 非功能条款编号(如"非阻断 bottom sheet,N-06")
- **tokens 具体化**:颜色给 hex、字号给 px/行高、间距给 4pt 网格值、
  组件给尺寸——编码工具可直接消费
- **prompts 规范**:英文;每条含 Style anchor(首屏定义基调);描述布局
  与元素,不描述业务背景
- 全程中文(§5 prompts 除外,英文)
- 设计决策不臆造 PRD 之外的"新功能"(UI 层只能呈现 PRD 已有功能)

## 5. 错误处理

- PRD 缺功能规格节(格式不符)→ 降级:按 P0 清单推导页面并标注"推导自 P0"
- 推导屏数 > 6 → 按里程碑优先(覆盖 P0 全流程 + P1 主打),其余屏并入
  §4 附注
- Stitch MCP 工具存在但调用失败 → 该屏降级手动,继续其余屏

## 6. 验收

1. 对既有 PRD(qr-code-generator)真跑 `/cat-ui`,产出 6 节文档,核对:
   每屏有功能 ID 来源、tokens 具体、prompts 含 Style anchor
   *(2026-08-25 实施时改用 pdf-scanner PRD 做泛化验收——更强的测试:
   非演示品类,且与演示版对照仍可完成;qr-code-generator 的规范文档
   已由演示阶段产出)*
2. 与演示产物对照:结构一致,质量不低于演示版
3. 智能后端分支:MCP 未配置时正常走手动路径(当前会话即此状态,天然可测);
   MCP 配置后(后续步骤)复跑验证自动生成分支

## 7. 非目标

- 不直接在 Figma 里画图(Figma MCP 是另一条可选路径,本 skill 不绑定)
- 不做交互原型/动效规格
- 不重新发明设计系统模板(6 节结构固定)
- 不做 A/B 风格方案(风格从 PRD 定位唯一推导)
