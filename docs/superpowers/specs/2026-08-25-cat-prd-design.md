# 品类报告 → 自包含 PRD 生成(/cat-prd) — 设计文档

**日期:** 2026-08-25
**状态:** 已确认
**前置:** 品类竞品与痛点分析(2026-08-25)已上线,产出 `reports/{日期}-品类分析-{slug}.md`

## 1. 背景与目标

品类分析链路(`/cat-scan`)已能产出某品类的竞争格局、功能矩阵、用户痛点与机会点
报告。下一步的自然需求:把报告变成**可执行的产品需求文档(PRD)**——用户选定
定位后,得到一份能直接交给 AI 编码工具(Claude Code/Cursor 等)**依次实现**的
自包含需求文档。

**核心决策(用户确认):**

| 维度 | 决定 |
|---|---|
| 形态 | 可复用能力:新 skill `/cat-prd`(纯文档,零代码) |
| 自包含 | PRD 拿到**其他项目/其他 AI 会话**直接可用,不依赖本项目任何上下文 |
| 交互 | 生成前固定问 3 个决策,其余全部由 AI 从报告推导 |
| PRD 组织 | 10 节结构;功能分 P0/P1/P2;每功能带可测试验收标准(AC) |

**职责边界:** skill 只做"报告 → PRD"的推导与写作;不做原型、不做技术选型
实现(技术栈由 PRD 读者按能力替换)。

## 2. 命令形态

```
/cat-prd <品类 slug> [ios|android|cross] [buyout|subscription|free-ad]
```

- slug 用于定位 `reports/*-品类分析-{slug}.md`;用户也可给品类名,由 AI 模糊
  匹配最近的报告并复述确认
- 两个可选参数预答交互问题(见下);未给的进交互

## 3. 生成流程(四步)

1. **定位报告**:按 slug 找品类报告。找不到 → 提示先跑 `/cat-scan {品类}`,
   停止。
2. **交互 3 问**(报告里没有、必须人来定的决策;已由命令参数回答的跳过):
   - 目标平台:ios / android / cross
   - 商业模式:buyout(买断)/ subscription(订阅)/ free-ad(免费+广告);
     AI 附报告证据辅助(如"买断制在本品类有 4.9 分口碑溢价")
   - 主定位:列出报告第 6 节机会点供选择,或选"AI 推荐"(AI 按痛点强度 ×
     竞争空白推荐并给理由)
3. **推导生成**:AI 从报告提取竞品基准、痛点证据、功能矩阵,按 §4 结构写作
4. **落盘**:`reports/{今天日期}-PRD-{slug}.md`;输出 3-5 句执行摘要
   (一句话定位、P0 范围、里程碑数)

## 4. PRD 文档结构(10 节,全自包含)

| # | 节 | 内容与来源 |
|---|---|---|
| 0 | 使用说明(给 AI 编码工具) | 按里程碑依次实现;每功能对照 AC 自验;技术栈可按团队能力替换但功能契约不变 |
| 1 | 产品概述 | 品类定义与背景(报告第 1 节内联)、一句话定位 |
| 2 | 目标用户与核心场景 | 从报告推导细分人群与场景 |
| 3 | 定位与差异化主张 | 选定机会点展开:主张 + 痛点证据(评论摘录+频率)内联,论证"为什么是我" |
| 4 | 竞品基准表 | 头部 3-5 家:主要功能/特色/价格/评分/下载量(从报告第 2/4 节**内联复制**) |
| 5 | 功能规格(主体) | **P0=品类标配基线**(来自报告标配清单,缺了就不算该品类);**P1=差异化主打**(直接支撑选定定位);**P2=亮点增强**。每功能:ID(F-P0-01)/名称/描述/AC/依赖 |
| 6 | 非功能需求 | 从痛点推导(性能/隐私/离线等,如"全程本地处理"对应隐私痛点) |
| 7 | 变现设计 | 选定模式具体方案(定价/免费额度),显式列出规避的竞品痛点(如不设水印陷阱) |
| 8 | 里程碑与实现顺序 | P0→P1→P2;P0 内部按技术依赖排序;每里程碑有"完成定义" |
| 9 | 附录 | 名词表、数据来源与快照日期声明 |

## 5. 质量约束

- **自包含硬约束**:全文禁止"见品类报告 X 节"式引用,一切证据/表格/数字内联
- **数字不臆造**:竞品评分/下载量/价格只从品类报告抄录,PRD 标注数据快照日期
- **AC 可测试**:每条验收标准描述可观察、可验证的行为(✓"扫描 10 页导出单个
  PDF 且页序正确";✗"体验流畅");写不出 AC 的功能须重想描述
- 全程中文;技术名词保留英文

## 6. 错误处理

- 报告不存在 → 提示先跑 `/cat-scan {品类}`,停止
- 报告缺机会点节(格式不符/旧版)→ 降级:让用户口述主定位再继续
- 报告快照 > 90 天 → 提示数据可能过时、建议重跑 `/cat-scan`,不阻塞

## 7. 验收

skill 无代码,验收靠真跑:

1. 对 PDF 扫描报告真实生成一份 PRD,人工核对:10 节齐全、P0-P2 分层合理、
   AC 可测试、无外部引用
2. **自包含性实测**:PRD 单独交给一个全新 subagent(模拟外部 AI 编码工具,
   不给任何其他上下文),令其仅凭 PRD 排出 P0 实现顺序——无需追问即成功

## 8. 非目标

- 不做交互原型/UI 稿
- 不做技术栈选型的实现细节(由 PRD 读者决定)
- 不自动触发 AI 编码工具(PRD 生成即止;实现发生在别的会话)
- 不生成后端/服务端设计(纯客户端 app 视角;PRD 中涉及云同步等仅写到
  功能契约层)
