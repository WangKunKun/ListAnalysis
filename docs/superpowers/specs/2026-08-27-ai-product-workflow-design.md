**日期:** 2026-08-27
**状态:** 已确认
**前置:** 《App Store 非国区工具榜扫描工作流》(2026-08-22)已上线运行

## 1. 背景与目标

现有系统定期扫描App Store工具榜并生成分析报告。本设计将分析能力延伸到产品创建全流程：**从榜单分析 → 品类洞察 → 产品需求文档(PRD) → UI界面生成**，实现数据驱动的产品设计闭环。

**成功标准：**
- 一条命令完成从数据分析到产品UI生成的完整流程
- 每个环节可独立调用或链式执行
- 智能推荐有潜力的产品方向
- 生成的UI界面包含完整的交互状态

**核心决策(用户确认):**

| 维度 | 决定 |
|---|---|
| 架构 | 独立skill链式架构，分步执行+智能推荐 |
| 品类分析 | 组合分析：市场机会+竞争格局+功能缺口 |
| PRD生成 | 交互式选择，基于品类分析生成结构化PRD |
| UI生成 | 分层转换+交互状态生成，自动调用Stitch MCP |
| 流程控制 | 分步执行(独立调用) + 智能推荐(系统推荐最优方向) |

## 2. 整体架构

## 3. Skills职责和实现

### /category-analysis (新增)

**核心功能：**

1. **多维度分析引擎**
   - 市场规模分析：基于app数量、评分、下载量推算
   - 功能缺口分析：从用户评论中提炼未满足需求
   - 竞争强度分析：头部产品集中度、价格竞争态势

2. **智能推荐算法**
   ```python
   机会评分 = (市场需求强度 × 0.4) + (竞争蓝海度 × 0.3) + 
             (技术可行性 × 0.2) + (用户痛点强度 × 0.1)
   ```

3. **交互选择界面**
   - 文本表格展示候选品类
   - 每个品类显示：推荐度星标、市场机会描述、难度评估
   - 用户通过序号或名称选择

**输入输出：**
- 输入：`data/{日期}/apps.json` + 分析报告
- 输出：`reports/{日期}-品类分析.md` + 推荐摘要

### /generate-prd (更新现有)

**更新策略：**

1. **结构化模板填充**
   - 基于品类特征选择合适的PRD模板
   - 从品类分析报告中提取关键数据
   - 补充行业标准功能模块

2. **用户编辑机制**
   - 生成PRD后展示摘要供预览
   - 提供编辑模式调整功能需求和优先级
   - 支持保存多个版本

**PRD文档结构(10节)：**
```
0. 使用说明(给AI编码工具)
1. 产品概述
2. 目标用户与核心场景
3. 定位与差异化主张
4. 竞品基准表
5. 功能规格(P0/P1/P2分级，每项含验收标准)
6. 非功能需求
7. 变现设计
8. 里程碑与实现顺序
9. 附录
```

### /generate-stitch-ui (更新现有)

**分层转换策略：**
```
PRD文档 → 功能分解 → UI界面规划 → Stitch Prompt生成
                    ↓
            ┌───────────┼───────────┐
            ↓           ↓           ↓
       首页prompt  功能页prompt  设置页prompt
            ↓           ↓           ↓
       交互状态扩展  交互状态扩展  交互状态扩展
```

**交互状态生成规则：**

| 交互类型 | 状态变体 |
|---------|----------|
| 点击类(按钮) | 常态、悬停态、禁用态、点击后态 |
| 选项卡 | 选中态、未选中态、切换中态 |
| 列表项 | 空态、单条态、多条态、加载态 |
| 表单输入 | 空值态、填写中态、已填写态、错误态 |
| 导航类 | 首页态、子页面态、返回态 |

## 5. Stitch MCP集成设计

### 智能检测和调用

**检测策略：**
```python
def detect_stitch_mcp() -> bool:
    available_tools = list_mcp_tools()
    return any('stitch' in tool.name.lower() for tool in available_tools)
```

**调用流程：**
1. **基础检测** - 启动时检查Stitch MCP可用性
2. **逐屏生成** - 按优先级：默认态 → 交互状态 → 错误状态
3. **重试机制** - 单屏失败重试一次，再失败降级为手动
4. **状态追踪** - 记录生成成功/失败的屏数和原因

### Stitch Prompt生成

**Style Anchor结构：**
```
主色: #3B82F6 (蓝色系)
字体: Inter, 16px基础字号
风格: 现代简洁、注重效率
画布: 375×812px (iPhone尺寸)
```

**每屏Prompt结构：**
```
Screen X - 屏幕名称 [F-P0-01, F-P0-02]

[默认态]
Create a modern mobile app screen for [功能描述]...
[详细布局和元素描述]

[交互状态]
Create the same screen but with [状态描述]...
[状态变化的具体描述]
```

## 6. 错误处理和降级策略

### 分层错误处理

**Level 1 - 数据获取错误：**
- 品类分析数据缺失 → 提示先运行 `/category-analysis`
- PRD文档过期(>90天) → 警告但可继续，标注数据来源日期
- Stitch MCP不可用 → 自动降级为手动prompts输出

**Level 2 - AI分析错误：**
- 品类样本<5个 → 提示关键词可能不当，建议调整
- PRD功能缺失 → 降级为基础UI框架
- 状态生成失败 → 跳过该状态，继续其他状态

**Level 3 - 生成错误：**
- 单屏Stitch调用失败 → 重试1次，再失败跳过该屏
- 部分状态生成失败 → 生成已成功的状态，标注失败部分
- 全部失败 → 完整文档已产出，提供手动路径

### 降级策略矩阵

```
失败类型                  → 降级路径
─────────────────────────────────────────
品类分析失败              → 手动输入品类信息
PRD生成失败              → 使用标准模板生成基础PRD
UI推导失败               → 生成通用设计系统
Stitch MCP全部失败        → 输出prompts文档
部分屏生成失败           → 混合模式(自动+手动)
```

## 7. 质量约束和验收标准

### 质量约束体系

**文档质量：**
- 所有输出文档必须**自包含**，可独立使用
- PRD中每个功能必须包含**可测试的验收标准**
- UI规范必须包含**具体数值**（hex颜色、px尺寸等）
- 禁止外部引用，所有数据和证据必须**内联**

**生成质量：**
- 品类分析必须覆盖**至少10个样本**
- 智能推荐必须基于**数据驱动的评分**
- 交互状态必须覆盖**所有UI变化场景**
- Stitch prompts必须包含**Style anchor**保证一致性

**可追溯性：**
- 每个UI屏幕必须标注**来源功能ID**
- 每个设计决策必须引用**PRD条款编号**
- 每个推荐必须提供**数据支撑理由**

### 验收标准

**品类分析验收：**
- [ ] 生成完整的竞争格局和功能矩阵
- [ ] 用户提供3-5个推荐品类，每个包含机会分析
- [ ] 痛点提炼包含具体评论证据和频率统计

**PRD生成验收：**
- [ ] PRD包含10节完整结构
- [ ] 每个功能都有可测试的AC
- [ ] 竞品数据完整且来源清晰

**UI生成验收：**
- [ ] 每个屏幕都有对应的Stitch prompt
- [ ] 交互状态覆盖完整
- [ ] Stitch MCP调用成功或提供明确降级路径

**端到端验收：**
- [ ] 完整流程：分析 → PRD → UI → Stitch生成
- [ ] 各环节可独立调用
- [ ] 智能推荐准确度高

## 9. 风险控制

### 技术风险

- **Stitch MCP服务不稳定** → 多级降级策略，prompts始终可用
- **AI分析质量波动** → 建立质量评估标准和人工审核机制
- **数据获取失败** → 缓存机制和重试策略

### 产品风险

- **推荐准确性不足** → 持续优化算法，收集用户反馈
- **生成的UI质量不稳定** → 建立质量评估标准和模板库
- **用户需求变化** → 保持架构灵活性，支持快速迭代

## 10. 非目标

- 不做历史趋势对比（聚焦当期分析）
- 不做A/B风格方案（风格从PRD唯一推导）
- 不直接在Figma画图（聚焦Stitch MCP路径）
- 不做后端/服务端设计（纯客户端app视角）
