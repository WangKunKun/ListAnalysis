# PRD → UI 设计规范与 Stitch 生成

读 PRD(`reports/{日期}-PRD-{slug}.md`),零交互推导出 UI 设计规范文档
(含每屏可直接粘贴的 Stitch prompts);若会话中有 Stitch MCP 工具则
自动生成设计稿,没有则 prompts 即交付物。设计决策全部从 PRD 推导,不问用户。
设计文档:docs/superpowers/specs/2026-08-25-cat-ui-design.md

## 流程(三步)

1. **定位 PRD**:`reports/` 下按 slug 匹配 `*-PRD-{slug}.md`(多份取最新)。
   找不到 → 提示先跑 `/cat-prd {品类}`,停止。PRD 日期距今 > 90 天 →
   提示不阻塞。通读 PRD(重点:定位主张、功能规格 P0-P2、非功能需求、
   变现设计与里程碑)。
2. **推导设计并产出文档** `reports/{今天日期}-UI设计规范-{slug}.md`,
   6 节结构见下。
3. **智能后端分支**:检查会话可用工具中是否有名称含 `stitch` 的 MCP 工具
   (含 ToolSearch 发现)——
   - **有**:逐屏用文档 §5 的 prompt 调 Stitch 生成;单屏失败重试一次,
     再失败该屏降级手动;生成完回报结果与导出状态
   - **没有**:文档 prompts 即交付物
   - MCP 失败不影响文档产出(文档永远完整)

## 文档结构(6 节)

1. **设计方向**:从 PRD 定位推导 3 个关键词 + 风格基调(每词注明推导
   来源:定位/品类痛点/功能特征);声明"UI 层只呈现 PRD 已有功能"
2. **设计系统 tokens**:色板(浅/暗双色模式,hex)、字阶(字号/行高/字重)、
   间距(4pt 网格)/圆角/阴影(克制:全 app ≤3 处阴影)、核心组件规格
   (按钮/输入框/卡片/导航,给尺寸)
3. **信息架构与页面流**:导航结构图(ascii),页面从功能块推导;
   核心 ≤6 屏,超出按里程碑优先(覆盖 P0 全流程 + P1 主打,其余 §4 附注)
4. **页面详细规范**:每屏——目的 / 布局(自上而下区域描述)/ 关键元素 /
   交互状态 / 空态。**每屏标题后标注来源功能 ID**(如 "Screen 1 创建页
   [F-P0-01, F-P0-02]");付费/打断类 UI 决策必须引用 PRD 非功能条款编号
   (如"非阻断 bottom sheet,N-06")
5. **每屏 Stitch prompts(英文)**:统一的 Style anchor 放节首(主色/字体/
   风格关键词/画布尺寸),每屏一段 prompt,布局与元素描述,不含业务背景;
   节首附一句使用方法(先贴首屏定基调,其余屏带 anchor 保证一致)
6. **交付与衔接**:给 Stitch(手动路径步骤)/ 给 Figma(导出后按 §2 tokens
   核对的要点)/ 给编码工具(tokens + 页面契约与 PRD AC 的对应关系)

## 质量约束

- 功能可追溯:每屏有功能 ID 来源;UI 决策引用 PRD 条款编号
- tokens 具体化:hex/px/pt 全给值,编码工具可直接消费
- 设计不臆造 PRD 之外的新功能
- 文档全程中文(§5 prompts 英文)
- 数字/竞品引用只能来自 PRD(不得引入外部信息)

## 错误处理

- PRD 缺功能规格节(格式不符)→ 降级按 P0 清单推导页面,文档标注
  "推导自 P0 清单"
- 推导屏数 > 6 → 按里程碑优先裁剪,§4 附注被并入的屏
- Stitch MCP 调用失败 → 降级手动,继续其余屏
